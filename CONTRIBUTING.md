# Contributing to VectorStep

**VectorStep is open source, but not open contribution.**

The code is Apache-2.0 licensed and you are genuinely welcome to use it, run it,
modify it, and fork it. What the project does not accept is external code
contributions. Pull requests will be closed unmerged, regardless of how good
they are — this is a policy about provenance, not a judgement about your patch.

The reason is simple: VectorStep is maintained by a single author, and keeping
the copyright history unambiguous matters more to the project's future than the
occasional merged fix. [SQLite](https://www.sqlite.org/copyright.html) operates
the same way, for the same reason.

## What is very welcome

- **Bug reports.** Open an issue. Steps to reproduce, what you expected, what
  happened, and the version you were running are usually enough.
- **Feature requests and use cases.** Especially the ones that explain what you
  were trying to do, not just what you want added.
- **Questions about how something works.** If the docs did not answer it, that
  is useful signal on its own.
- **Reports that the documentation is wrong or confusing.** These are treated as
  bugs.

Please describe problems in prose rather than pasting a suggested patch. A
report is more useful than a diff, and it keeps the contribution boundary clean
for both of us.

## What happens to pull requests

They get closed with a link to this file. Nothing personal — please do not take
the trouble to open one.

## Forking

Forking is explicitly fine and the licence permits it. If you need behaviour the
project does not provide, maintaining your own fork is a legitimate answer and
you will get no argument here. The only thing you may not do is use the
VectorStep name or logo in a way that implies your fork is endorsed by or
affiliated with this project.

## Getting in touch

If you would rather just talk to a person — about a use case, whether something
is a bug, or anything else — you can reach me at **alex@vectorstep.io**.

## Security issues

Please do not open a public issue for a suspected vulnerability. See
[SECURITY.md](SECURITY.md).
